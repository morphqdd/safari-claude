# Окно чата Safari Agent (фаза 2) — дизайн

Дата: 2026-11-15 · Статус: на согласование · Основа: `2026-11-14-safari-claude-design.md` (фаза 1 — MCP для Claude Code, сделана и проверена вживую).

## 1. Зачем

Фаза 1 даёт Claude управлять Safari из терминала. Владелец хочет то же, что даёт Claude in Chrome: чат всегда под рукой рядом со страницей, без терминала. Задачу пишешь прямо в Safari, Claude выполняет её в твоём Safari и показывает, что делает.

Условия фазы 1 остаются в силе: только подписка через Claude Code (наш код не ходит в API Anthropic), только для себя, не мешать параллельной работе, ноль активности в простое.

## 2. Цели, не-цели, анти-цели

**Цели**
- Отдельное окно чата в Safari: диалог, ответы Claude по мере написания, лента действий, кнопка Stop.
- Три способа открыть: кнопка расширения на панели инструментов, сочетание клавиш, пункт контекстного меню «Спросить Claude про эту страницу».
- Подтверждения рискованных действий и разрешения сайтов — карточками прямо в чате.
- Диалог продолжается до «Новый чат» и переживает перезапуск Safari.

**Не-цели**
- Боковая панель внутри страницы (отвергнута, §4).
- Несколько диалогов одновременно, список истории диалогов, поиск по ним.
- Вложения, загрузка файлов, выбор модели в окне.
- Инструменты кроме Safari (Bash, файлы, веб-поиск) в режиме чата.

**Анти-цели — провал, даже если работает**
- Страница может прочитать, что владелец пишет в чат, или подделать/нажать карточку подтверждения.
- Живой процесс `claude` или таймеры, когда чатом не пользуются.
- Чат и Claude Code в терминале одновременно управляют Safari.
- Рискованное действие выполняется без явного нажатия «Разрешить» владельцем.

## 3. Как это видит владелец

```
┌ Claude ─────────────── [Новый чат] ┐
│ Вы: найди билеты на Ласточку на сб │
│ Claude: Открываю rzd.ru…           │
│   · открыл rzd.ru                  │
│   · ввёл «Москва» в поле «Откуда»  │
│   · нажал «Найти»                  │
│ ┌ Подтвердите ─────────────────┐   │
│ │ Нажать «Купить» на rzd.ru?   │   │
│ │      [Разрешить] [Отказать]  │   │
│ └──────────────────────────────┘   │
├────────────────────────────────────┤
│ [ сообщение…            ] [Stop]   │
└────────────────────────────────────┘
```

- **Окно:** узкое (≈400 px) окно Safari справа от основного, открытое как страница расширения.
- **Открытие:** кнопка на панели, сочетание клавиш или пункт меню открывают окно или выводят его вперёд, если оно уже открыто.
- **«Спросить Claude про эту страницу»:** вкладка, на которой вызвано меню, становится вкладкой агента, окно чата открывается.
- **Ответы:** текст Claude появляется по мере написания; каждое действие — строка в ленте («открыл…», «нажал…»).
- **Stop:** в окне чата и на плашке на странице. Кнопка на панели инструментов больше не Stop, а открывает чат (решение владельца).
- **Подтверждения:** рискованный клик/ввод/клавиша — карточка «Разрешить / Отказать». Новый сайт — «Один раз / Всегда / Нет».
- **Занято:** если Safari уже управляет Claude Code из терминала, чат показывает «Занято другой сессией» и не отправляет задачу.
- **Новый чат:** кнопка начинает новый диалог; старый не хранится.

## 4. Подходы

1. **Окно-страница расширения (выбран).** Отдельное окно Safari с HTML-страницей расширения. Переходы агента его не трогают, оно одно на все вкладки. Страницы сайтов не имеют к нему доступа: не видят нажатий клавиш и не могут нарисовать поверх него поддельную карточку. Тот же стек (JS), что у расширения.
2. **Панель внутри страницы (из исходной спеки, отвергнута).** Ближе всего к боковой панели Chrome, но стирается при каждом переходе, закрывает часть страницы, попадает на скриншоты, а главное — события клавиатуры из closed shadow root всплывают к `document`, и любой сайт может записывать, что владелец пишет Claude.
3. **Нативное окно приложения Safari Agent на SwiftUI (отвергнуто).** Безопасно, как 1, но больше нового кода и живёт вне Safari.

## 5. Устройство

### 5.1 Части

- **Окно чата** — `extension/chat/chat.html` + JS. Общается только с фоновой страницей расширения (`runtime` messaging / port).
- **Фоновая страница** — открывает/находит окно чата (`windows.create`, тип popup, если Safari его поддерживает, иначе обычное окно), регистрирует контекстное меню и команду, пересылает сообщения между окном чата и helper по уже существующему WebSocket.
- **Демон helper** — новый модуль «чат»: запускает и держит процесс `claude`, переводит его поток событий в сообщения для окна чата, хранит id сессии.
- **`claude`** — запускается демоном:
  `claude -p --input-format stream-json --output-format stream-json --include-partial-messages --strict-mcp-config --mcp-config <файл> --tools "" --allowedTools "mcp__safari__*" [--resume <id>]`
  в рабочей папке `~/Library/Application Support/SafariClaude/workspace`. MCP-конфиг указывает на `safari-claude-helper mcp` с переменной окружения, помечающей сессию как чатовую.

### 5.2 Поток сообщения

1. Владелец пишет в окне → фоновая страница → демон (`chat.send`).
2. Демон проверяет блокировку: если её держит терминальная сессия — ответ «занято». Иначе запускает `claude` (или использует живой) и пишет сообщение пользователя в его stdin в формате stream-json.
3. `claude` вызывает инструменты через `safari-claude-helper mcp` → демон, как в фазе 1. Блокировку при этом берёт чатовая сессия.
4. События `claude` (части текста, вызовы инструментов, итог) демон пересылает окну чата (`chat.event`). Строки ленты строятся из вызовов инструментов.
5. По окончании ответа окно снова принимает ввод.

### 5.3 Подтверждения в режиме чата

- В терминальном режиме подтверждение — это запрос разрешения Claude Code на `confirm_action`. В чате этого запроса нет, поэтому `confirm_action` из чатовой сессии **сам** ждёт решения владельца: демон отправляет окну чата карточку и блокирует вызов до нажатия кнопки (или Stop / закрытия окна = отказ).
- Отличить чатовую сессию демон может по метке, которую несёт MCP-процесс, запущенный демоном (переменная окружения → поле в `hello`). Метку нельзя получить извне: её знает только демон, который сам запускает `claude` (одноразовый секрет на запуск).
- Правило фазы 1 сохраняется: обычный `click`/`type`/`key` на рискованном элементе отказывает с подсказкой вызвать `confirm_action`.
- Разрешение сайта «Всегда» пишется в существующее хранилище `sc.sites`; «Один раз» действует до конца текущего ответа.

### 5.4 Жизненный цикл и простой

- `claude` запускается по первому сообщению и завершается через 5 мин без сообщений (`claudeIdle`); следующее сообщение продолжает диалог через `--resume <id>`.
- Id сессии хранится на диске (`~/Library/Application Support/SafariClaude/chat-session`); «Новый чат» его удаляет.
- История для показа в окне хранится в `browser.storage.local` расширения (последний диалог), чтобы окно восстановилось после перезапуска Safari.
- Закрытое окно чата не останавливает текущий ответ; Stop — останавливает (завершает ход `claude` и отклоняет дальнейшие вызовы инструментов, как в фазе 1).
- Демон не завершается по `idleExit`, пока жив `claude`.

### 5.5 Открытие

- Кнопка на панели: `browserAction.onClicked` → открыть/вывести окно чата.
- Сочетание клавиш: `commands` в манифесте, не больше двух модификаторов (ограничение Safari, проверено в фазе 1). Предложение: ⌃⇧K. Работает, когда Safari на переднем плане.
- Контекстное меню: `contextMenus`/`menus` «Спросить Claude про эту страницу» → вкладка становится вкладкой агента (`tab_select`) + открыть окно.

## 6. Безопасность

- Окно чата — страница расширения: сайты не видят её DOM и ввод.
- Чатовый `claude` получает только `mcp__safari__*` (`--tools ""` отключает встроенные, `--strict-mcp-config` — чужие MCP-серверы из настроек владельца).
- Содержимое страниц — недоверенные данные (prompt injection): в системный промпт чата (`--append-system-prompt`) добавляется правило не выполнять инструкции со страниц и спрашивать перед необратимыми действиями.
- Карточка подтверждения показывает домен и текст элемента, полученные демоном, а не текст от модели.

## 7. Риски, проверить первыми (spike)

1. Поддерживает ли Safari `windows.create({type: "popup"})`, размер и позицию окна; как ведёт себя окно расширения при перезапуске Safari.
2. `contextMenus` в Safari MV2 и `commands` с ⌃⇧K.
3. Формат stream-json ввода/вывода текущей версии Claude Code (2.1.311): сообщения пользователя, частичные сообщения, конец хода, прерывание хода по Stop без убийства процесса.
4. Работает ли `--tools ""` вместе с `--allowedTools "mcp__safari__*"` так, что никакой запрос разрешения не возникает (иначе в `-p` он будет автоматически отклонён).
5. Влияет ли открытое окно чата (в фокусе) на условия фазы 1 (`windowFocused`, фоновые вкладки): ожидается, что клики через AX продолжают работать, ввод — через DOM.

## 8. Решения автора спеки (уточнения после проверки)

Эти пункты владелец не обсуждал; это решения автора, их можно оспорить.

1. **Ожидание подтверждения.** Вызов `confirm_action`, ждущий карточку, — обычный вызов «в работе»: блокировка держится, `lockIdle` не срабатывает. Таймаута нет. Stop, закрытие окна чата или отключение расширения = отказ. Для `kind: "site"` ответ одно из `once | always | no`; `once` действует до конца текущего ответа Claude (демон помнит домен до конца хода), `always` пишется в `sc.sites`.
2. **Метка чатовой сессии.** Демон при каждом запуске `claude` генерирует случайный секрет и передаёт его в окружении (`SC_CHAT_KEY`); `safari-claude-helper mcp` кладёт его в `hello` новым необязательным полем `chat`. Демон сравнивает с текущим секретом; несовпадение = обычная терминальная сессия.
3. **Блокировка.** Проверка «занято» — при `chat.send`: если блокировку держит терминальная сессия, ответ «занято». Иначе демон сразу резервирует блокировку за чатом на весь ход (до конца ответа Claude), поэтому терминал в середине хода получит «занято», а не перехватит Safari. После конца хода действует обычный `lockIdle` 120 с.
4. **Stop.** Прерывает текущий ход: если stream-json позволяет прервать ход — прерываем, иначе завершаем процесс `claude`, а следующее сообщение продолжит диалог через `--resume`. Флаг Stop для чата снимается следующим сообщением владельца. Stop в окне чата останавливает любую текущую задачу, в том числе запущенную из терминала.
5. **Spike — первая веха плана.** Если ответ отрицательный: нет popup-окна → обычное окно, если и оно не удерживается → вкладка; нет `contextMenus` → пункт меню убрать (остаются кнопка и сочетание); нет `commands` → сочетание убрать; если `--tools "" --allowedTools "mcp__safari__*"` всё равно даёт запросы разрешения → `--permission-mode bypassPermissions` (у чатового `claude` нет других инструментов, а `confirm_action` сам ждёт карточку).
6. **«Спросить Claude про эту страницу».** Только делает вкладку вкладкой агента (это делает фоновая страница расширения, как `tab_select` в фазе 1) и открывает окно; текст страницы не отправляется, поле ввода получает фокус. Если блокировку держит терминал — вкладку не менять, показать «занято».
7. **Путь к `claude`.** Как в установщике фазы 1 (`/opt/homebrew/bin/claude`, иначе `PATH`); `install` записывает найденный абсолютный путь в конфиг, потому что у launchd короткий `PATH`. Вход в Claude Code берётся из профиля пользователя (`HOME` задан launchd) — проверить в spike.
8. **Неудачный `--resume`** (сессия удалена/устарела): начать новую сессию, в окне показать строку «Предыдущий диалог недоступен, начат новый»; старая история остаётся видимой выше этой строки.

## 9. Оставлено строителю

- Вёрстка окна чата и формулировки строк ленты.
- Формат сообщений `chat.*` между окном, фоновой страницей и демоном.
- Точный текст системного промпта чата.
- Обработка ошибок запуска `claude` (не найден, не залогинен) — показать понятное сообщение в окне.
