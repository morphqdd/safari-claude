# Safari-агент на Claude Code — дизайн

Дата: 2026-11-14 · Статус: черновик на согласование · Рабочее название: `safari-claude` (пользовательское имя без бренда Anthropic, выберем позже)

## 1. Зачем

Владелец переходит на новый Mac и хочет жить в Safari ради энергоэффективности. Ему нужен аналог Claude in Chrome: Claude сам работает в **его обычном Safari** (его логины, его вкладки) — открывает страницы, читает, кликает, вводит, листает, делает скриншоты и доводит задачу до конца.

Ключевые условия, заданные владельцем:

- **Работает по подписке через Claude Code**, без API-ключа. Модель вызывает только сам Claude Code; наш код никогда не ходит в API Anthropic и не использует токены Claude Code.
- **Для себя.** Не для App Store, не для других людей.
- **Видно, что делает Claude:** свой нарисованный курсор и подсветка действий, как в Claude in Chrome.
- **Не мешает работать параллельно:** не забирает фокус, не двигает настоящий курсор, Safari может быть в фоне и на другом рабочем столе (Space).
- **Ноль затрат в простое:** никаких фоновых процессов, таймеров и соединений, пока задачи нет. Helper поднимается автоматически по первому сообщению.

## 2. Цели, не-цели, анти-цели

**Цели**
- Полный набор браузерных инструментов уровня Claude in Chrome (см. §6).
- Два входа в одного агента:
  1. **Claude Code в терминале** — инструменты Safari подключены как MCP-сервер.
  2. **Панель чата в Safari** — пишешь задачу прямо в браузере, helper запускает Claude Code в headless-режиме.
- Визуализация действий (курсор, подсветка, статус, «Стоп»).
- Подтверждения рискованных действий и разрешения по сайтам.

**Не-цели (v1)**
- iOS/iPadOS, App Store, раздача другим людям, мультипользовательность.
- Запуск задач по расписанию.
- Полный паритет с Chrome в фоновых вкладках: там нет настоящих кликов и скриншотов (§7.5). Владелец решил: «когда упрёмся — тогда и будем думать».

**Анти-цели — провал, даже если «работает»**
- Агент перехватывает фокус или клавиатуру владельца (активирует Safari, вызывает `AXFocused`).
- Двигает настоящий курсор без явного запасного режима и уведомления.
- Любая фоновая активность CPU/сети в простое (опрос, keep-alive, постоянный WebSocket, живой процесс `claude`).
- Необратимые действия (отправка, оплата, удаление) без подтверждения.

## 3. Ограничения среды

- macOS 26.6, Safari 26.6, Xcode 27.2 (выбран через `xcode-select`), Swift 6.3.
- Claude Code 2.1.311 по пути `/opt/homebrew/bin/claude`. У процессов launchd в PATH нет `/opt/homebrew/bin` → helper запускает `claude` по абсолютному пути (настраивается).
- JS расширения Safari не может запускать процессы; нативный обработчик расширения живёт в App Sandbox и не может запустить `claude` или читать `~/.claude`. Нужен отдельный процесс вне песочницы — helper.
- У расширений Safari нет `chrome.debugger` (CDP) и нет `sidePanel`.
- Service worker расширения Safari непостоянный, выгружается в любой момент.

## 4. Подходы к действиям на странице (выбор сделан)

| Подход | Суть | Почему нет / да |
|---|---|---|
| A. Только DOM-события из content script | `el.click()`, `dispatchEvent` | Нет: события `isTrusted: false`, ломаются сложные редакторы, загрузка файлов, часть защит |
| B. Гибрид с системной мышью (CGEvent) | реальные события ОС по экранным координатам | Нет как основной: двигает курсор, требует Safari впереди — мешает параллельной работе |
| C. WebDriver (`safaridriver`) | автоматизация Safari | Нет: работает в отдельных заблокированных окнах, не в вкладках и сессии владельца |
| **D. Accessibility + расширение (выбрано)** | клики через `AXPress`, фокус через `element.focus()` из расширения, ввод — клавиши напрямую процессу Safari | Да: подтверждено экспериментом (§5) |

Системная мышь (B) остаётся **только** как явный запасной путь для случаев, где D не справился, с уведомлением владельцу. В v1 можно не реализовывать — решение исполнителя.

## 5. Результаты эксперимента (2026-11-14)

Проверено на macOS 26.6 / Safari 26.6, страница логировала события на локальный сервер, «передний план» опрашивался через `lsappinfo` каждые 100 мс.

| Действие | Механизм | `isTrusted` | Фокус Safari не забирает |
|---|---|---|---|
| Клик по кнопке/ссылке | `AXUIElementPerformAction(el, kAXPressAction)` | ✅ true (`focus→mousedown→mouseup→click`) | ✅ |
| Фокус в поле | `element.focus()` из content script | ✅ | ✅ (3/3 прогона) |
| Ввод текста | `CGEvent` с `keyboardSetUnicodeString` + `postToPid(safariPid)` | ✅ (`keydown/beforeinput/input/keyup`) | ✅ |
| Окно на другом Space | приватный `_AXUIElementCreateWithRemoteToken`, перебор id 0..2000 | — | ✅ |
| Сопоставление DOM → AX | поиск по атрибуту `AXDOMIdentifier` (= DOM `id`) | ✅ найден и нажат | ✅ |

**Запрещено (подтверждено, что ломает анти-цели):**
- `kAXFocusedAttribute = true` — выводит Safari на передний план.
- `NSRunningApplication.activate` / AppleScript `activate` — перехватывает ввод владельца.
- `kAXValueAttribute` для записи текста — записал значение не в то поле; ненадёжно.
- `AXPress` по текстовому полю — фокус не ставит.

**Мелочи:** при `virtualKey: 0` событие `keyup` приходит с буквой текущей раскладки — нужны корректные коды клавиш (для спецклавиш — обязательно). `NSWorkspace.frontmostApplication` в CLI без run loop возвращает устаревшее значение — для проверок не использовать.

**Не проверено (риски, проверить первыми, §11):** скриншот окна на другом Space; видимость неактивных вкладок в AX; сопоставление по классу вместо `id`; спецклавиши (Enter, Tab, стрелки, сочетания) через `postToPid`; iframes.

## 6. Инструменты агента (MCP)

Сервер MCP с именем `safari`. Набор по образцу Claude in Chrome:

| Инструмент | Что делает |
|---|---|
| `tabs_list` | вкладки и окна Safari (id, url, заголовок, какая вкладка агента) |
| `tab_create(url?)` | открыть вкладку агента (в окне агента, см. §7.5) |
| `tab_select(tabId)` | переключить агента на вкладку |
| `navigate(url \| "back" \| "forward" \| "reload")` | навигация во вкладке агента |
| `read_page(filter?)` | снимок страницы: дерево интерактивных и текстовых элементов с `ref`, ролью, именем, состоянием, видимостью |
| `find(query)` | найти элементы по тексту/описанию → `ref` |
| `get_text(ref?)` | текст страницы или элемента (для чтения статей и т. п.) |
| `click(ref)` | клик |
| `type(ref, text, submit?)` | фокус + ввод текста |
| `key(combo)` | нажатие клавиш/сочетаний (Enter, Tab, Esc, ⌘A…) |
| `scroll(ref? \| direction, amount?)` | прокрутка |
| `screenshot()` | скриншот видимой части вкладки агента |
| `wait(ms \| for: ref/text)` | ожидание |

`ref` — стабильный в пределах снимка идентификатор, который content script связывает с DOM-узлом, а helper — с AX-элементом.

## 7. Архитектура

```
Claude Code (подписка)
   │ stdio MCP: `safari-claude-helper mcp`  (Claude Code сам запускает этот подпроцесс)
   ▼
helper-демон (Swift, вне песочницы, LaunchAgent, socket activation на 127.0.0.1)
   ├─ AX-исполнитель: AXPress, ввод клавиш в процесс Safari, поиск окон (в т. ч. на других Space)
   ├─ мост к расширению: WebSocket
   └─ режим чата: запускает /opt/homebrew/bin/claude (stream-json, --resume) с MCP-конфигом на себя
   ▲
   │ WebSocket 127.0.0.1 + токен
Safari-расширение (MV3, в приложении-контейнере)
   ├─ service worker: соединение с helper'ом, вкладки, captureVisibleTab
   └─ content script: снимок страницы, ref↔DOM, focus(), оверлей (курсор, подсветка, статус, «Стоп»), панель чата
```

### 7.1 Helper

- Один Swift-бинарник (SwiftPM), два режима:
  - **демон** — запускается launchd по входящему соединению;
  - **`mcp`** — stdio MCP-сервер, который Claude Code запускает как подпроцесс; подключается к демону (тем самым активируя его) и проксирует вызовы.
- **Автостарт:** `~/Library/LaunchAgents/<label>.plist` с ключом `Sockets` (`127.0.0.1`, фиксированный порт), без `RunAtLoad`/`KeepAlive`. Демон получает сокет через `launch_activate_socket`.
- **Выход по простою:** демон завершается, когда одновременно нет подключений, нет живого `claude` и нет незавершённых вызовов, дольше `idleExit` (по умолчанию 10 мин). Процесс `claude` в режиме чата завершается через `claudeIdle` (по умолчанию 5 мин) после последнего ответа; session id сохраняется на диск, продолжение через `--resume`.
- **Accessibility-разрешение** выдаётся бинарнику helper'а. Чтобы оно не слетало при пересборке, бинарник подписывается стабильной идентичностью (сертификат Apple Development), а не ad-hoc.
- **Поиск окна Safari:** сначала `kAXWindowsAttribute`; если окна нет (другой Space) — приватный `_AXUIElementCreateWithRemoteToken`. Если приватный путь перестал работать — AX-путь недоступен для окна на другом Space, агент работает DOM-путём и сообщает об этом в логе действий.
- **Никогда** не вызывает `activate`, `AXFocused`, не пишет `AXValue`.

### 7.2 Расширение

- Safari Web Extension MV3 внутри минимального приложения-контейнера (Xcode, `safari-web-extension-converter`/шаблон). Приложение-контейнер — только оболочка, плюс экран первичной настройки (разрешения, установка LaunchAgent).
- **Простой = ноль:** content script при загрузке страницы ничего не делает, кроме регистрации слушателя сообщений; никаких таймеров/MutationObserver, пока агент не работает в этой вкладке. Service worker подключается к helper'у только при наличии задачи или открытой панели, после завершения — закрывает соединение. Переподключение при выгрузке worker'а.
- **ref ↔ DOM ↔ AX:** при снимке content script помечает элементы временной меткой (предпочтительно класс `__sc_ref_N`; если AX не отдаёт классы — временный `id` только у элементов без своего `id`, снимается после действия). Helper находит AX-элемент по `AXDOMIdentifier`/`AXDOMClassList` внутри окна агента.
- `all_frames: true` для iframe — поведение проверить (§11).

### 7.3 Последовательность действий

Каждое действие выбирает один из двух путей:

- **Настоящий путь (AX)** — вкладка агента активна в своём окне (тогда она есть в дереве Accessibility).
- **DOM-путь** — вкладка в фоне. События генерирует content script (`isTrusted: false`), в логе действий помечаются.

Действия:

- `click(ref)`: content script прокручивает элемент в видимость, анимирует курсор, ставит метку → AX-путь: helper находит AX-элемент → `AXPress`; DOM-путь или AX-элемент не найден: полная цепочка `pointerdown/mousedown/pointerup/mouseup/click` из content script → «пульс», метка снимается.
- `type(ref, text)`: курсор к полю → `el.focus()` в content script → если AX-путь **и Safari не на переднем плане** — helper посылает символы в процесс Safari с корректными кодами клавиш; иначе — DOM-ввод (`beforeinput`/`input`, вставка через нативный сеттер value / `execCommand('insertText')` для contenteditable). Правило «не слать клавиши, пока Safari впереди» нужно потому, что `postToPid` отдаёт ввод активному окну Safari, а владелец печатает в Safari параллельно (не проверено, считаем риском утечки ввода в обе стороны).
- `key(combo)`: по тем же правилам — клавиши в процесс Safari, когда безопасно, иначе `KeyboardEvent` из content script.
- `screenshot`: только когда вкладка агента видима — `tabs.captureVisibleTab`, если окно в фоне/на другом Space и это не сработало — захват окна через ScreenCaptureKit (владелец разрешил «Запись экрана»). Вкладка в фоне → инструмент возвращает понятную ошибку с советом использовать `read_page`.

### 7.4 Оверлей (то, что видит владелец)

- Свой курсор «➤ Claude» (оранжевый), плавно летит к цели перед каждым действием, клик — анимация «пульса».
- Рамка вокруг текущего элемента; при вводе — подсветка поля, текст появляется посимвольно (это и есть реальный ввод).
- Плашка внизу вкладки: «● Claude: <что делает>» и кнопка **«Стоп»** (мгновенно прерывает задачу: helper отменяет текущий вызов и останавливает `claude`).
- Лёгкое свечение краёв вкладки, пока агент в ней работает.
- Всё в Shadow DOM, `pointer-events: none` везде, кроме кнопок; не влияет на страницу и исчезает после задачи.

### 7.5 Где работает агент

Как в Claude in Chrome: агент работает **во вкладках окна владельца**. Своя вкладка открывается в фоне (`tabs.create({ active: false })`) рядом с текущей, без переключения вкладок у владельца; по просьбе агент работает и в текущей вкладке владельца. Вкладки агента помечены: свечение краёв и плашка в оверлее, префикс «● » в заголовке, пока агент работает.

Владелец переключился на вкладку агента — агент сам переходит на настоящий путь (AX, скриншоты); ушёл — обратно на DOM-путь. Никаких переключений вкладок и активаций окна со стороны агента.

У Safari владельца все страницы в одном окне (новые окна открываются вкладками), поэтому отдельное окно агента не используем. Групп вкладок для расширений в Safari нет.

### 7.6 Панель чата в Safari

- Открывается кнопкой расширения на панели инструментов; рисуется в странице (Shadow DOM, справа), т. к. `sidePanel` нет, а popup закрывается при потере фокуса.
- Показывает диалог, поток ответов Claude и ленту действий.
- Под капотом: helper запускает `claude -p --input-format stream-json --output-format stream-json --mcp-config <на себя> --allowedTools "mcp__safari__*"` в отдельной рабочей папке (`~/Library/Application Support/<app>/workspace`), без Bash и файловых инструментов.

## 8. Безопасность

- Демон слушает только `127.0.0.1`; WebSocket требует токен (генерируется при установке, передаётся расширению через контейнер песочницы и нативный обработчик — §9); проверка `Origin` = `safari-web-extension://<id>`.
- Режим чата: только инструменты `mcp__safari__*`.
- **Разрешения по сайтам:** перед первым действием на новом домене — запрос в оверлее «Разрешить Claude действовать на example.com? Один раз / Всегда / Нет». Стоп-лист по умолчанию (банки, госуслуги, менеджеры паролей) — редактируемый.
- **Подтверждения:** перед кликом, который content script классифицирует как рискованный (submit формы с полями пароля/оплаты, кнопки с текстом вроде «Оплатить/Купить/Отправить/Удалить/Send/Pay/Delete», `type=submit` в формах оплаты), — модальное подтверждение в оверлее. Плюс инструкция в системном промпте агента спрашивать перед необратимыми действиями.
- Содержимое страниц — недоверенные данные (prompt injection); в описаниях инструментов и промпте это указано.

## 9. Решения владельца

- Только для себя, по подписке через Claude Code.
- Подход D (Accessibility + расширение), с видимым курсором Claude.
- Safari может быть в фоне и на другом рабочем столе.
- Автостарт helper'а по первому сообщению, ноль ресурсов в простое.
- Xcode установлен для постоянной установки расширения.
- Владелец печатает в Safari параллельно с работой агента.
- Агент работает во вкладках окна владельца, как в Chrome; ограничения фоновых вкладок принимаются («упрёмся — подумаем»).
- Apple-аккаунт **бесплатный** (Personal Team): без App Groups и платных возможностей. Токен для WebSocket helper кладёт в контейнер песочницы расширения (helper вне песочницы и может туда писать), нативный обработчик расширения читает его оттуда. Helper подписывается сертификатом «Apple Development» персональной команды, чтобы разрешение Accessibility не слетало при пересборке.
- Разрешение «Запись экрана» допустимо (для скриншотов через ScreenCaptureKit).

## 10. Решения, принятые мной (можно оспорить)

- Два входа (Claude Code + панель в Safari), порядок: сначала MCP из Claude Code, потом панель.
- Helper на Swift (socket activation, AX — нативно).
- Транспорт расширение↔helper — WebSocket с токеном (XPC — позже, если понадобится).
- Таймауты: `claude` 5 мин, демон 10 мин.
- Системная мышь как запасной путь — не в v1.
- **Подтверждения из терминала:** рискованные действия (§8) идут отдельным инструментом `confirm_action(ref, kind)`, который не входит в автоматически разрешённые — Claude Code сам спросит владельца в терминале своим стандартным запросом разрешения. Обычный `click` на рискованном элементе отказывает с подсказкой использовать `confirm_action`. В режиме панели чата подтверждение — модальное окно в оверлее Safari.
- **Разрешения по сайтам из терминала:** первое действие на новом домене возвращает ошибку «домен не разрешён»; разрешить можно в оверлее/настройках расширения или через `confirm_action(kind: "site")` (тот же запрос Claude Code).
- **Одна задача за раз:** если Safari уже управляет другой клиент (вторая сессия Claude Code или панель), новый получает ошибку «занято». «Стоп» останавливает текущую задачу.

## 11. Риски — проверить в начале реализации

1. Видимость фоновых вкладок в AX (если видны — настоящий путь доступен и в фоне; это улучшение, не блокер).
2. Утечка ввода между окнами при `postToPid`, когда владелец печатает в Safari; альтернатива — `AXSelectedText` на конкретном элементе (тест подготовлен, не прогнан).
3. `captureVisibleTab` для окна в фоне / на другом Space; иначе ScreenCaptureKit.
4. Сопоставление DOM→AX по классу (`AXDOMClassList`); иначе — временный `id`.
5. Спецклавиши и сочетания через `postToPid` в фоне.
6. iframes (в т. ч. cross-origin) — content script и AX.
7. Бесплатный аккаунт: устойчивость Accessibility-разрешения при пересборке, срок действия подписи/профиля расширения, нужно ли периодически заново включать расширение.
8. Переподключение при выгрузке service worker'а посреди задачи.
